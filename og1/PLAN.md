# План: применение системы курса к «Онлайн Гимназии №1» (og1.ru)

**Статус:** черновик, не согласован детально, не начат в реализации. Собран по итогам
изучения материалов курса (`materials/`, см. корневой [`CLAUDE.md`](../CLAUDE.md)) и сайта
[og1.ru](https://og1.ru). Нужна доработка (Шаблон А, воронка, прайс) и явное «поехали» перед
началом кода — см. [`docs/agents/issue-tracker.md`](../docs/agents/issue-tracker.md) для того,
как заводить тикеты, когда до этого дойдёт.

---

## 1. Бизнес

**Онлайн Гимназия №1** — лицензированная дистанционная общеобразовательная школа, 3–11 класс,
с государственной аккредитацией и аттестатом.

**Тарифы (аналог прайса):**

| Тариф | Формат | Цена |
|---|---|---|
| «Школьный» | очно, живые уроки | от 28 310 ₽/мес |
| «Ученический» | очно-заочно, потоковые лекции | 0–23 100 ₽/мес |
| «Любознательный» | самоподготовка | 124–500 ₽/мес |
| «Аттестация» | прикрепление для аттестации | 15 000 ₽ |
| Индивидуальные репетиторы | подготовка к экзаменам | **по запросу** (не фикс. цена) |

**Текущая воронка на сайте:** пробный день (3 урока + 7 дней доступа) → заявка/консультация
менеджера → подбор тарифа → дистанционная подача документов → договор → оплата (в т.ч.
рассрочка через Тинькофф).

**Каналы:** телефон 8 (800) 700-75-01, email, Telegram-канал, форма заявки на каждой странице,
24/7 чат в мобильном приложении платформы.

**ЦА:** родители детей 8–18 лет — мобильные семьи, спортсмены, те, кто уходит с очной школы
(травля, неудобный график, переезд/эмиграция, семейное обучение).

## 2. Маппинг конвейера курса на og1

Полный конвейер описан в [`CLAUDE.md`](../CLAUDE.md) (шаги 0–10). Ниже — как каждый шаг
ложится на приёмную комиссию школы.

| Шаг курса | Что делает система | Как это для og1 |
|---|---|---|
| 1. Ловец лидов (ручной) | Разовый прогон промпта по выгрузке из группы | Родительские Telegram/ВК-чаты про семейное обучение, «перевести ребёнка на дистант», спорт+учёба, переезд/эмиграцию |
| 2. Скоринг входящего | Userbot слушает личку/группы, LLM-судья 0–100 | Нужен свой **Шаблон А**: боли (травля, гибкий график, спорт, переезд, СО), слова-сигналы («аттестация», «дистант», «семейное обучение») |
| 3. Догрев затихших | Лесенка польза → доверие → мягкий дедлайн | Переносится без изменений |
| 4. Эскалация → заявка | Определяем позицию, создаём заявку, маршрутизация в отдел | «Отдел» = приёмная комиссия / подбор тарифа. Если тариф стандартный → прайс; если «индивидуальные репетиторы» → движок КП (см. п.3) |
| 5. Оплата (бот-кассир) | Карточка заказа + «Оплатил ✅» | **Требует адаптации** — см. п.4 |
| 6. Напоминания о неоплаченном | Лесенка +30 мин / +1 день / +3 дня | Переносится, но триггер — не «оплата товара», а «бронь пробного дня / незавершённая заявка» |
| 7. CRM и статус | Путь статусов, видимый лиду | Переименовать: `Заявка → Пробный день → Документы → Договор → Оплачено → Зачислен` |
| 8. Защита от инъекций | Эвристика + LLM-классификатор до любого LLM-вызова | Переносится без изменений, но см. п.5 (данные о несовершеннолетних) |
| 9. Движок КП | Код считает сумму по формуле, LLM только матчит состав | Прямое попадание — см. п.3 |
| 10. Производственная очередь | Priority Score + обратное планирование, ограниченная «пропускная способность» | Нет цеха, но есть родственная идея — см. п.3 |

## 3. Особенно хорошие совпадения

- **Движок КП (шаг 9) ≈ расчёт пакета для репетитора.** Стандартные тарифы — это готовый
  «прайс» (как каталог товаров в исходном ТЗ). А «индивидуальные репетиторы по запросу» —
  ровно тот случай, под который писался движок: не фиксированная цена, а расчёт по параметрам
  (предметы, часы в неделю, уровень, срок) из справочника ставок. Движок так же может
  read-only ответить тёплому лиду «ориентировочно от ~X ₽/мес» ещё до разговора с менеджером.
- **Производственная очередь (шаг 10) ≈ ограниченность мест в классе.** Нет цеха и часов
  работы, но есть та же логика ограниченной ёмкости: «малые классы до 22 человек»,
  «забронировать место на новый учебный год». Приоритизацию заявок на класс можно считать
  той же механикой (Priority Score), просто ресурс — не станко-часы, а место в классе.

## 4. Что не переносится напрямую

- **Оплата не разовая, а по подписке** + рассрочка через Тинькофф + подписание договора.
  «Нажал „Оплатил“ → paid» из исходного ТЗ слишком просто для этого цикла сделки. Реалистичнее:
  бот доводит лида до передачи менеджеру приёмной комиссии, а не завершает сделку кнопкой
  самостоятельно. Финальный шаг (документы/договор) остаётся на человеке.
- **Тон и этика касаний.** Здесь не «продажа детали», а деликатные темы (недовольство школой,
  травля ребёнка, переезд семьи) — прогрев и скоринг должны быть мягче и осторожнее, чем в
  примере автосервиса/мебели из исходного ТЗ.

## 5. Открытый риск, который нужно решить до старта

**Персональные данные несовершеннолетних.** В отличие от автосервиса/цеха, здесь диалог
неизбежно касается данных о ребёнке (возраст, школа, причина ухода, иногда — деликатные
обстоятельства вроде травли). Это требует:
- проверить соответствие 152-ФЗ (обработка ПДн, тем более о детях) до того, как LLM начнёт
  вести диалог с автосохранением контекста;
- решить, какие данные вообще можно хранить в `dialog_context`/`leads` и как их обезличивать;
- возможно, потребуется юридическая консультация заказчика — вне зоны технической реализации.

Это блокер для боевого запуска, не для планирования — просто нужно держать в голове с самого
начала проектирования схемы БД и промптов.

## 6. Чего не хватает, чтобы начать реализацию

- **Шаблон А** — описание бизнеса/ЦА/болей/голоса og1 (сейчас есть только в общем виде из сайта).
- **Воронка этапов** (аналог 1–16 из исходного ТЗ) — путь родителя от «интересуется» до
  «ребёнок зачислен».
- **Прайс/справочник** — тарифы + ставки репетиторов по предметам для движка КП.
- **Слова-сигналы** для мониторинга родительских групп.
- **Решение по риску из п.5** — до того, как проектировать схему БД лидов.
- Явное подтверждение от пользователя, что можно приступать к спеке/тикетам под og1
  (пока это не запрошено).
