# og1 — бот приёмной комиссии (MVP на заглушках)

Реализация конвейера курса «Альфа Курс» (см. корневой [`CLAUDE.md`](CLAUDE.md)) под бизнес
«Онлайн Гимназия №1» (og1.ru) — план в [`og1/PLAN.md`](og1/PLAN.md).

## Как это работает, простыми словами

**Пример.** Ты открываешь CRM → раздел «Ловец лидов» (`/catcher`) → вставляешь ссылку на
открытый чат/группу (Telegram или VK) → жмёшь «Выгрузить сейчас». Дальше всё дальше — сам:

1. **Автовыгрузка.** Отдельный служебный аккаунт (не боевой продающий) читает только новые
   сообщения из этого чата с прошлого раза.
2. **Поиск тёплых людей.** ИИ прогоняет каждое сообщение через промпт «Ловец тёплых лидов» —
   ищет не по ключевым словам, а по смыслу тех, кто *ищет решение* прямо сейчас.
3. **Кандидаты в CRM.** В `/catcher` появляется список: цитата, повод, ссылка на профиль,
   готовый черновик первого сообщения.
4. **Ты пишешь первым.** Единственный ручной шаг во всей цепочке — ты (или менеджер) сам
   заходишь в разговор. Бот не может написать лиду первым, пока тот не нажал Start — это
   ограничение самого Telegram.
5. **Человек ответил → включается автопилот.** Каждое входящее сообщение сначала проверяется
   на попытки взлома промптом, затем (если это не вопрос о статусе своего заказа) получает
   балл 0–100 по гайду скоринга.
6. **Балл решает реакцию.** 0–19 холодный → бот молчит. 20–79 тёплый/горячий → бот сам
   пишет уместное сообщение под этап воронки. 80–100 кипящий → эскалация к менеджеру.
7. **Если лид затих — бот сам напоминает** по лесенке: день → польза без CTA, 3 дня →
   кейс/доверие, неделя → мягкий дедлайн, дальше цикл останавливается. Новое сообщение от
   лида сбрасывает счётчик.
8. **Кипящий лид → заявка и цена.** Из переписки достаётся, что человек хочет. Если это
   тариф с фиксированной ценой — берётся прайс; если кастом (например, индивидуальный
   репетитор) — движок КП сам считает цену по формуле, без участия человека.
9. **Передача к оплате/менеджеру.** Лиду уходит ссылка на отдельного бота-хэндоффа (кнопки
   умеет показывать только он, не боевой userbot). Менеджеру в CRM падает карточка
   «горячий лид». Для og1 сделку до конца доводит человек (подписка + договор + рассрочка
   слишком сложны для одной кнопки «Оплатил»).
10. **Всё видно в CRM.** `/orders` — канбан заявок (Заявка → В работе → ... → Зачислен).
    Двигаешь карточку — лиду автоматически уходит уведомление о смене статуса.

Итог одной строкой: ты даёшь боту «удочку» (ссылку на чат) → он сам вылавливает тёплых
людей → сам прогревает → сам считает цену → сам доводит до горячей заявки и отдаёт готового
к сделке человека менеджеру. Ручные точки — вставить ссылку, написать первому лиду и закрыть
саму сделку (пока для og1 нет самообслуживающейся оплаты).

## Что уже сделано

Полный код на плейсхолдерных бизнес-данных (тарифы og1 реальные, ставки репетиторов и
воронка — плейсхолдер): userbot-скоринг, guard от инъекций, генерация касаний, движок КП
для репетиторов, бот-хэндофф (передача менеджеру вместо кнопки «Оплатил»), лесенка
напоминаний, веб-CRM, и автовыгрузка чатов для шага 1 «Ловец лидов» (раздел `/catcher`).
28 юнит-тестов чистой логики, все зелёные. `main.py` запускается и стабильно работает без
единого реального ключа (userbot/бот-хэндофф просто не стартуют с понятным warning, CRM
поднимается всегда).

**Не в этом MVP:** реальный платёжный провайдер, PaaS-деплой, production-очередь/Priority
Score (аналог мест в классе — см. og1/PLAN.md п.3, явно решено не реализовывать 2026-08-12).

## Быстрый старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env  # заполнить реальные TG_API_ID/HASH, BOT_TOKEN, ANTHROPIC_API_KEY
.venv/bin/pytest -q   # 28 тестов чистой логики, без реального Telegram/LLM
```

Первый логин боевого userbot'а продаж:

```bash
.venv/bin/python login.py            # интерактивный вход по номеру телефона
.venv/bin/python export_session.py   # печатает TG_STRING_SESSION для .env
```

Первый логин ОТДЕЛЬНОГО аккаунта для автовыгрузки чатов (шаг 1, `/catcher`) — не тот же
аккаунт, что боевой userbot:

```bash
.venv/bin/python login.py            # запустить ещё раз под другим номером/сессией → CATCHER_TG_STRING_SESSION
.venv/bin/python vk_browser_login.py # VK: открывает окно браузера, входите в VK руками, потом Enter в терминале
```

VK без токена: `vk_browser_login.py` один раз открывает обычное окно Chromium на профиле
`secrets/vk_browser_profile`, вы сами входите в VK (лучше запасным аккаунтом) и жмёте Enter —
скрипт проверяет вход и сохраняет его. Пароль скрипт не спрашивает и не видит. Папка профиля
даёт доступ к аккаунту VK — обращаться как с паролем. Если VK разлогинит профиль, обход VK
закончится ошибкой «браузер ловца не залогинен» — просто запустите скрипт ещё раз. Нужен
Playwright и браузер: `.venv/bin/pip install -r requirements.txt` (в venv от uv без pip —
`uv pip install --python .venv/bin/python -r requirements.txt`), затем `.venv/bin/python -m playwright install chromium`.

Запуск всей системы (userbot + бот-хэндофф + CRM + фон):

```bash
.venv/bin/python main.py
```

По умолчанию `DRY_RUN=1` и `SCHEDULER_ENABLED=0` — бот считает балл и логирует, что бы
ответил, но реально в Telegram не пишет и фоновые задачи не крутятся. Включать осознанно
в `.env` после ручной обкатки на логах. Без `TG_API_ID/HASH` userbot просто не стартует
(warning в логе), без `BOT_TOKEN` — не стартует бот-хэндофф; CRM на `uvicorn` поднимается
в любом случае.

CRM защищена логином/паролем (не токеном в URL) — создать первого пользователя один раз:

```bash
.venv/bin/python manage_users.py add admin   # спросит пароль (минимум 8 символов)
```

CRM: `http://127.0.0.1:8080/` — дашборд, `/orders` — канбан заявок, `/catcher` — ловец лидов.
Открыть любой роут без сессии — редирект на `/login`. `CRM_SECRET_KEY` в `.env` подписывает
cookie-сессию — сгенерировать свой: `python -c "import secrets; print(secrets.token_hex(32))"`.
Управление пользователями — `manage_users.py add/passwd/list/remove`.

Рендер — Jinja2 + HTMX (`templates/`, `static/`), без сборки и без CDN-зависимостей
(htmx вендорен в `static/vendor/`).

## Без LLM-ключа

Если `ANTHROPIC_API_KEY` не задан — скоринг, guard, касания и П1-поиск кандидатов уходят в
эвристический фолбэк (ключевые слова, шаблонные тексты) вместо падения, см. `llm.py`.

## Автовыгрузка чатов (шаг 1 «Ловец лидов», `/catcher`)

Отдельный от боевого userbot'а конвейер (см. `.scratch/lead-catcher-auto/spec.md`):
1. В `/catcher` добавляете ссылку на открытую Telegram-группу или VK-сообщество.
2. Жмёте «Выгрузить сейчас» — тянутся только новые сообщения с прошлого прогона
   (`catcher_tg.py`/`catcher_vk.py`), затем прогоняются через промпт П1 (`catcher_pipeline.py`).
   VK по умолчанию читается браузером (`vk_browser.py`): посты сообщества за
   `CATCHER_MAX_MESSAGE_AGE_DAYS` и комментарии под ними (с ветками ответов). Новые комментарии
   падают и под старые посты, поэтому каждый обход заново проходит посты в этом окне, дубли
   отсекаются базой. Темп человеческий: паузы, одна вкладка, не больше 40 постов с комментариями
   за обход. Ссылки принимаются и с vk.ru / m.vk.com, в карточке кандидата из VK — имя автора и
   кнопка на его страницу vk.com/…
   **Беседы VK** (родители общаются в чатах сообщества, а не на стене). Как подключить:
   1) вступите в беседу аккаунтом ловца в его браузере — `.venv/bin/python vk_browser_login.py`
      (в открывшемся окне перейдите по приглашению vk.me/join/… или вступите со страницы
      сообщества; пока бот делает обход, окно не открывать — профиль нельзя открыть дважды);
   2) откройте беседу и пришлите в «➕ Добавить чат» адрес из строки браузера вида
      `https://vk.com/im/convo/2000000001` (подходят и vk.ru, и старый `vk.com/im?sel=c1`).
      Ссылки на все беседы аккаунта печатает `.venv/bin/python vk_browser.py chats`.
   Приглашение vk.me/join/… само по себе не подходит. Беседа только читается (без кликов и
   ввода, но открытие отмечает сообщения прочитанными): история листается колесом вверх до
   прошлого обхода (курсор — номер сообщения в беседе), при первом обходе — до
   `CATCHER_MAX_MESSAGE_AGE_DAYS`, не больше 1500 сообщений за обход. Ссылка «💬 Беседа VK» в
   карточке просто открывает беседу — публичных ссылок на сообщения бесед у VK нет.
3. Находки — в таблице кандидатов (цитата, повод, ссылка, готовый заход). Бот сам никому не
   пишет первым — переходите по ссылке и заходите в разговор вручную, отмечайте «написал».

Нужны ОТДЕЛЬНЫЕ секреты от боевого userbot'а: `CATCHER_TG_API_ID/HASH/STRING_SESSION` и
вход в VK через `vk_browser_login.py` (профиль браузера в `secrets/vk_browser_profile`, путь
меняется `VK_BROWSER_PROFILE_DIR`). Необязательно: если задан `VK_ACCESS_TOKEN` (получить через
`vk_login.py`, нужен свой `VK_APP_ID` — Standalone-приложение на vk.com/apps?act=manage), VK
читается через API — только посты, без комментариев.

## Диалоги в ВК (`vk_messenger.py`)

Тот же продавец, что в Telegram, но в личке VK. Транспорт — настоящий браузер (Playwright, headless)
на профиле `secrets/vk_browser_profile`, куда оператор вошёл через `vk_browser_login.py`.
**Это основной личный аккаунт VK — поэтому по умолчанию выключено и с жёсткими лимитами.**

**Как работает.**
1. Ловец нашёл кандидата в VK → вы сами пишете ему первым и жмёте «✅ Написал» в карточке кандидата.
   Бот первым не пишет никогда.
2. Раз в `VK_SALES_POLL_SECONDS` (≈3 мин) поллер открывает vk.com/im и смотрит в списке диалогов только
   строки из белого списка: кандидаты VK со статусом «написал» и VK-лиды, уже заведённые в базе.
   Короткое имя профиля (vk.com/elenell) один раз переводится в числовой id (открывается страница
   профиля, результат кэшируется в таблице `vk_peers`). Чужие диалоги не открываются, беседы — тоже.
3. Есть непрочитанное или сменилось последнее сообщение → открывается этот диалог, берутся новые
   сообщения. Ваше первое сообщение и всё, что вы пишете руками, попадает в историю репликой
   «менеджер» (как в Telegram). Если после сообщения лида вы уже ответили сами — бот молчит.
4. Ответ лиду считает то же ядро, что в Telegram (`main.process_lead_text`): защита от инъекций,
   скоринг, короткий ответ в стиле менеджера, при интересе — просьба о телефоне/способе связи
   («здесь, в ВК» вместо «в тг»), карточка в @ai_scouts_leads_og1_bot со ссылкой на профиль VK и
   кнопкой «✅ Передал специалисту», дальше — ручной режим. «Веду сам» и блокировка работают так же.
5. Перед ответом — пауза 20–90 с, текст печатается посимвольно, после отправки проверяется, что
   сообщение появилось. Прогрев/напоминания VK-лидам (если включены) уходят тем же путём через очередь.

**Включить:** в `.env` `VK_SALES_ENABLED=1`, затем перезапуск:
`launchctl kickstart -k gui/$(id -u)/ru.og1.leads`. Боевой режим (`DRY_RUN=0`) нужен, как и для
Telegram: при `DRY_RUN=1` ответы только пишутся в лог.

**Настройки** (`.env`, значения по умолчанию): `VK_SALES_POLL_SECONDS=180`, `VK_SALES_MAX_PER_HOUR=20`
(на аккаунт), `VK_SALES_MAX_PER_DIALOG_HOUR=6`, `VK_SALES_DELAY_MIN=20`, `VK_SALES_DELAY_MAX=90`,
`VK_SALES_LOCK_WAIT=600` (сколько ждать браузер, пока его держит обход ловца),
`VK_SALES_HOURS=9-22` (личку проверяем только в эти часы по Москве; пусто — круглосуточно),
`VK_CRAWL_MIN_HOURS=20` (VK-источник ловца обходится не чаще раза в N часов, остальные запуски
его пропускают; 0 — без ограничения). Частый опрос и обходы подряд VK принимает за бота и
показывает проверку (`challenge.html` с `hash429`) — тогда бот останавливает диалоги до ручного входа.

**Состояние:** ⚙️ Система в ТГ-агенте — строка «Диалоги в VK» (вкл/выкл, последний опрос, ошибки).

**Остановить:** `VK_SALES_ENABLED=0` + перезапуск. Если VK показал капчу, «подозрительную активность»
или аккаунт разлогинился — отправка останавливается сама, операторам приходит предупреждение;
после проверки в браузере (`vk_browser_login.py`) нажмите «▶️ Возобновить VK» в ⚙️ Система или
перезапустите бота.

**Риски и ограничения.**
- Автоматизация личного аккаунта против правил VK: при подозрении VK может потребовать капчу или
  ограничить аккаунт. Лимиты и паузы снижают риск, но не убирают его.
- Открытый ботом диалог VK отмечает прочитанным — на телефоне сообщения лида будут уже «прочитаны».
- Ответ приходит с задержкой до ~5 минут (опрос + пауза), это не мгновенный Telegram.
- Браузерный профиль общий с ловцом: пока идёт обход сообщества/беседы, диалоги ждут (ловец отдаёт
  браузер между источниками, диалоги получают его первыми). Внешние скрипты (`vk_browser_login.py`,
  `vk_browser.py chats`) при работающем боте запускать нельзя — Chromium не откроет профиль дважды.
- Разметка веб-мессенджера VK может смениться — тогда поллер перестанет видеть сообщения и напишет
  ошибку в ⚙️ Система. Голосовые в VK не расшифровываются: на вложения бот не отвечает, зовёт менеджера.
- Лид из VK лежит в той же таблице `leads` (`platform='vk'`, `vk_id`, `vk_path`), `tg_id` у него
  отрицательный (`-vk_id`) — колонка обязательная и уникальная.

## ТГ-агент оператора (`AGENT_BOT_TOKEN`)

Отдельный бот для владельца (доступ только для ID из `AGENT_ALLOWED_IDS`). Внизу чата — меню разделов:

- **📊 Сводка** — что произошло сегодня: новые люди, горячие (80+), заявки, находки ловца.
- **🔥 Лиды** — горячие, последние диалоги, заблокированные; карточка человека с баллом, заявкой
  и последними сообщениями, кнопка «Разблокировать».
- **🎣 Ловец** — обойти все чаты или один, листать новых кандидатов («✅ Написал» / «⏭ Дальше»),
  собрать Google-документ, добавить чат по ссылке или поставить на паузу.
- **📋 Заявки** — заявки по этапам, перевод на следующий этап (с подтверждением, лиду уходит уведомление).
- **⚙️ Система** — всё ли подключено; переключатели «Боевой режим» (`DRY_RUN`) и «Напоминания»
  (`SCHEDULER_ENABLED`) — применяются сразу и сохраняются в `.env`.
- **❓ Помощь**.

Свободный текст («кто сегодня самый горячий?», «что бот ответил @ivan?») уходит в Claude с
инструментами только на чтение + запуск обхода/документа; менять режимы и этапы модель не может —
только кнопками с подтверждением. История разговора хранится в БД (`agent_history`), `/new` — начать заново.
Код: `agent_bot.py` (диалог и инструменты), `agent_menu.py` (меню), `agent_format.py` (разметка Telegram).

## Важные решения, зафиксированные перед реализацией (2026-08-12)

- **ПДн детей** — в БД не хранятся свободнотекстовые детали о ребёнке (возраст, школа,
  причина ухода); только структурные поля для воронки/скоринга. Юридическая проверка
  по 152-ФЗ всё равно нужна до боевого запуска с реальными лидами (см. og1/PLAN.md п.5).
- **Оплата** — бот доводит заявку до передачи менеджеру приёмной комиссии (кнопка
  «Передать менеджеру ✅» в `bot.py`), а не завершает сделку сам — цикл og1 (подписка +
  рассрочка + договор) для этого слишком сложный для автоматической кнопки.
- **Бизнес-данные** — тарифы og1 (`catalog.py`) реальные с сайта; Шаблон А, воронка,
  ставки репетиторов, слова-сигналы (`prompts.py`) — плейсхолдеры, заменить при получении
  боевых данных от заказчика.
- **Production-очередь / Priority Score (шаг 10)** — не реализована: в og1/PLAN.md это лишь
  «особенно хорошее совпадение» (места в классе ≈ станко-часы), не подтверждённая фича.
- **lead-catcher-auto** — VK читается браузером на сессии из `vk_browser_login.py` (токен VK ID
  получить не удалось: «Security Error», бизнес-аккаунт заводить не стали); путь через токен
  `vk_login.py` остался запасным. Рейт-лимиты (FloodWaitError/VK code 6) — просто ждём и продолжаем, без ротации
  аккаунтов/прокси.

## Что осталось, чтобы система была полностью боевой

1. Реальные `TG_API_ID/HASH` + логин (`login.py`/`export_session.py`) для боевого userbot'а.
2. Реальный `BOT_TOKEN` от @BotFather для бота-хэндоффа.
3. Реальный `ANTHROPIC_API_KEY`.
4. (Опционально, для `/catcher`) отдельные `CATCHER_TG_*` и вход в VK через `vk_browser_login.py`.
5. Боевые данные из брифа: Шаблон А, воронка, ставка репетитора и % наценки, слова-сигналы.
6. После — включить `DRY_RUN=0`/`SCHEDULER_ENABLED=1` и дать боту чаты на прогон.

## Деплой на выделенный ПК: Docker + Tailscale (бесплатно, без публичного IP)

Система рассчитана на постоянную работу на одном выделенном ПК (не облако) и доступ к CRM
с других устройств только по логину/паролю через приватную сеть **Tailscale** — бесплатно
(до 100 устройств на аккаунт, не нужна карта), без проброса портов на роутере и без
публичной точки входа в интернет (актуально с учётом блокировок/нестабильности некоторых
зарубежных сервисов в РФ — см. обсуждение в истории задачи).

### 1. Собрать и поднять контейнер

```bash
cp .env.example .env   # заполнить секреты, как в разделе «Быстрый старт» выше
docker compose build
docker compose up -d
docker compose exec og1 python manage_users.py add admin   # первый пользователь CRM
```

БД (`og1_leads.db`) и telethon-сессии живут в Docker-volume `og1_data` — переживают
пересборку образа. Порт 8080 контейнера пробрасывается **только на `127.0.0.1` хоста**
(см. `docker-compose.yml`) — снаружи самого ПК он не виден в принципе, даже без файрвола.

### 2. Поставить Tailscale на ПК (один раз, вне Docker)

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

Залогиниться тем же Tailscale-аккаунтом на устройствах сотрудников (мобильное приложение
или клиент для ПК) — `tailscale.com/download`. После этого устройства видят друг друга по
приватным адресам `100.x.x.x`, доступ к ним отзывается мгновенно в консоли Tailscale
(admin console → Machines) без переустановки чего-либо на сервере.

### 3. Открыть CRM внутри tailnet с настоящим HTTPS (бесплатно)

`tailscale serve` сам выпускает TLS-сертификат для машины и проксирует на локальный
127.0.0.1:8080 — снаружи tailnet ничего не видно, внутри — обычный `https://`:

```bash
sudo tailscale serve --bg https / http://127.0.0.1:8080
```

CRM станет доступна сотрудникам по адресу вида `https://<имя-machine>.<tailnet>.ts.net`
(точный адрес покажет команда `tailscale serve status`) — с Tailscale-клиента на любом их
устройстве, логин/пароль CRM защищает уже второй слой поверх приватной сети.

### Проверка после перезагрузки ПК

`docker compose up -d` уже с флагом `restart: unless-stopped` — контейнер поднимется сам.
Tailscale и `tailscale serve` также переживают перезагрузку по умолчанию (демон стартует
с системой). Если CRM не открывается — сначала `docker compose ps` и `tailscale status`,
а не сразу пересборка/переустановка.
