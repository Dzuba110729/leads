# Алгоритм расчёта минимального складского запаса с учётом прогнозов производства (мебельное производство)

## 1. Цель и область применения

Алгоритм предназначен для расчёта минимального (страхового) уровня складского запаса сырья, комплектующих и фурнитуры на мебельном производстве, с учётом:

- планового (прогнозного) объёма производства;
- норм расхода материалов на изделие (спецификации, BOM);
- сроков поставки от поставщиков;
- вариативности спроса и надёжности поставок.

Результат работы алгоритма — величина **Zmin** (минимальный запас) по каждой номенклатурной позиции, а также точка заказа (**ROP — Reorder Point**).

---

## 2. Исходные данные

| № | Параметр | Обозначение | Источник данных |
|---|----------|-------------|------------------|
| 1 | Прогноз производства (шт. изделий/период) | Пф | План производства, отдел продаж/планирования |
| 2 | Спецификация изделия (норма расхода материала на 1 ед.) | Нр | Технологическая карта / BOM |
| 3 | Средний срок поставки материала (дни) | Тпост | Договор с поставщиком, история поставок |
| 4 | Отклонение (разброс) срока поставки | ΔТпост | Статистика по факту поставок за 6–12 мес. |
| 5 | Среднедневной расход материала | Рср | Расчётная величина (см. п.3) |
| 6 | Отклонение (разброс) дневного расхода | ΔР | Статистика фактического расхода |
| 7 | Уровень сервиса (вероятность отсутствия дефицита) | Ксл | Устанавливается управленческим решением (обычно 90–99%) |
| 8 | Текущий остаток на складе | Ост | Данные WMS/1C |
| 9 | Объём незавершённого производства в пути | НЗП | Данные производственного учёта |

---

## 3. Пошаговый алгоритм

### Шаг 1. Перевод прогноза производства в потребность в материалах

Для каждой номенклатурной позиции материала:

```
Потребность(период) = Пф(период) × Нр
```

Пример: прогноз — 500 корпусов шкафа/месяц; норма ЛДСП 16 мм на 1 корпус — 4,2 м². 
Потребность = 500 × 4,2 = 2100 м²/месяц.

### Шаг 2. Расчёт среднедневного расхода

```
Рср = Потребность(период) / Количество рабочих дней в периоде
```

### Шаг 3. Расчёт отклонения дневного расхода (ΔР)

Рассчитывается как среднеквадратичное отклонение фактического расхода материала за последние N периодов (рекомендуется 6–12 месяцев):

```
ΔР = √( Σ(Рфакт_i − Рср)² / (N−1) )
```

Если исторических данных недостаточно (новая позиция), используется экспертная оценка отклонения — например, ±20% от Рср.

### Шаг 4. Определение коэффициента уровня сервиса (Z-фактор)

Используется таблица значений нормального распределения:

| Уровень сервиса Ксл | Z-фактор |
|---|---|
| 90% | 1,28 |
| 95% | 1,65 |
| 97,5% | 1,96 |
| 99% | 2,33 |
| 99,9% | 3,09 |

### Шаг 5. Расчёт страхового (минимального) запаса

Формула учитывает вариативность и расхода, и срока поставки одновременно (комбинированная формула):

```
Zmin = Z × √( Тпост × ΔР² + Рср² × ΔТпост² )
```

Где:
- **Тпост** — средний срок поставки, дни;
- **ΔР** — отклонение дневного расхода;
- **Рср** — среднедневной расход;
- **ΔТпост** — отклонение срока поставки, дни;
- **Z** — коэффициент уровня сервиса.

Если срок поставки стабилен (ΔТпост ≈ 0), формула упрощается до:

```
Zmin = Z × ΔР × √Тпост
```

### Шаг 6. Расчёт точки заказа (Reorder Point, ROP)

```
ROP = Рср × Тпост + Zmin
```

Это уровень остатка на складе, при достижении которого необходимо формировать новый заказ поставщику.

### Шаг 7. Корректировка с учётом прогноза производства (динамическая часть)

Так как мебельное производство часто имеет сезонность и позаказный характер, минимальный запас корректируется коэффициентом прогнозного роста/падения спроса:

```
Zmin_корр = Zmin × Кпрогноз
```

Где:
```
Кпрогноз = Пф(будущий период) / Пф(базовый период)
```

Если прогноз на следующий месяц выше среднего за последние 3 месяца — минимальный запас увеличивается пропорционально; если ниже — уменьшается (но не ниже минимально допустимого технологического остатка).

### Шаг 8. Проверка ограничений

```
Zmin_итог = max( Zmin_корр , Zтехнологический_минимум )
```

Где **Zтехнологический_минимум** — минимальная партия/остаток, обусловленный требованиями поставщика (кратность упаковки, минимальный заказ — MOQ) или технологией производства (например, неснижаемый запас кромки под конкретный цвет).

### Шаг 9. Формирование управленческого сигнала

```
Если (Ост + НЗП) ≤ ROP → сформировать заявку на закупку
Объём заявки = Потребность(до следующей поставки) + Zmin_итог − (Ост + НЗП)
```

## 4. Блок-схема алгоритма (текстовое представление)

```
[Прогноз производства] 
        ↓
[Расчёт потребности в материалах через BOM]
        ↓
[Расчёт Рср и ΔР по истории]
        ↓
[Выбор Ксл → Z-фактор]
        ↓
[Расчёт Zmin (формула комбинированного риска)]
        ↓
[Расчёт ROP]
        ↓
[Корректировка на прогноз (Кпрогноз)]
        ↓
[Проверка технологического/MOQ ограничения]
        ↓
[Сравнение текущего остатка с ROP]
        ↓
   Остаток ≤ ROP? ──Нет──→ [Мониторинг продолжается]
        ↓ Да
[Формирование заявки на закупку]
```

## 5. Пример расчёта

**Материал:** ЛДСП 16 мм, цвет "Дуб сонома"

| Параметр | Значение |
|---|---|
| Прогноз производства | 500 корпусов/мес |
| Норма расхода на 1 корпус | 4,2 м² |
| Рабочих дней в месяце | 22 |
| Потребность в месяц | 2100 м² |
| Рср | 95,5 м²/день |
| ΔР (отклонение) | 15 м²/день |
| Тпост | 12 дней |
| ΔТпост | 3 дня |
| Ксл (требуемый) | 95% → Z = 1,65 |

**Расчёт Zmin:**

```
Zmin = 1,65 × √(12 × 15² + 95,5² × 3²)
Zmin = 1,65 × √(12 × 225 + 9120,25 × 9)
Zmin = 1,65 × √(2700 + 82082,25)
Zmin = 1,65 × √84782,25
Zmin = 1,65 × 291,17
Zmin ≈ 480,4 м²
```

**Расчёт ROP:**

```
ROP = 95,5 × 12 + 480,4 = 1146 + 480,4 ≈ 1626,4 м²
```

Вывод: заказ на новую партию ЛДСП "Дуб сонома" необходимо формировать, когда остаток на складе опустится до уровня ~1626 м².

## 6. Периодичность пересчёта

| Тип позиции | Рекомендуемая частота пересчёта |
|---|---|
| Основные материалы (ЛДСП, МДФ, кромка) | Ежемесячно / при обновлении плана производства |
| Фурнитура массового применения | Раз в квартал |
| Позиции под конкретный заказ (эксклюзивные ткани, фасады) | При каждом новом крупном заказе |
| Материалы с высокой волатильностью цен/поставок | Ежемесячно с контролем ΔТпост |

---

## 7. Рекомендации по внедрению

1. Автоматизировать сбор Рфакт и Тпост.факт из учётной системы (1С, ERP/WMS), чтобы ΔР и ΔТпост считались на реальных данных, а не экспертно.
2. Хранить BOM (спецификации) в актуальном состоянии — ошибка в норме расхода напрямую искажает Zmin.
3. Разделять уровень сервиса Ксл по классам ABC/XYZ-анализа: для критичных и нестабильных по спросу позиций — выше Ксл (98–99%), для стабильных и малозначимых — ниже (90%).
4. Учитывать MOQ и кратность поставки поставщика как нижнее ограничение, а не как расчётную величину.
5. Пересматривать Кпрогноз при значимых изменениях плана продаж (новая коллекция, сезонный пик, крупный корпоративный заказ).

---

## 8. Используемые обозначения (сводно)

- **Zmin** — минимальный (страховой) запас
- **ROP** — точка заказа (Reorder Point)
- **Пф** — прогноз производства
- **Нр** — норма расхода материала на единицу изделия
- **Рср** — среднедневной расход материала
- **ΔР** — отклонение дневного расхода
- **Тпост** — средний срок поставки
- **ΔТпост** — отклонение срока поставки
- **Z** — коэффициент уровня сервиса (по таблице нормального распределения)
- **Ксл** — целевой уровень сервиса (%)
- **MOQ** — минимальный объём заказа у поставщика

---

## 9. Пилотный расчёт

Цель пилота — проверить алгоритм на реальном ассортименте перед внедрением в ERP/WMS. Для пилота выбрано одно изделие с высокой оборачиваемостью и три материала к нему с разным профилем риска: собственное сырьё с коротким плечом поставки, импортная кромка со средним сроком и импортная фурнитура с длинным сроком и жёстким MOQ. Это покрывает три типовых сценария, которые встретятся в полном каталоге.

### 9.1. Объект пилота

**Изделие:** Шкаф-купе 3-дверный «Модерн»
**Прогноз производства (пилотный месяц):** 120 шт
**Рабочих дней в месяце:** 22
**Сезонный фактор (пилотный месяц — предновогодний пик):** Кпрогноз = 1,15 (прогноз на пилотный месяц на 15% выше базового 3-месячного среднего)

Из BOM изделия для пилота выбраны 3 позиции:

| Позиция | Норма расхода Нр | Тпост, дн | ΔТпост, дн | Целевой Ксл | Z |
|---|---|---|---|---|---|
| ЛДСП 16 мм «Дуб сонома» (корпус) | 3,8 м²/шт | 10 | 2 | 95% | 1,65 |
| Кромка ПВХ 0,4 мм (кромка корпуса, импорт) | 22 м.пог/шт | 15 | 4 | 97,5% | 1,96 |
| Направляющие раздвижные системы, компл. (импорт, MOQ = 100 компл.) | 1 компл./шт | 35 | 7 | 99% | 2,33 |

### 9.2. Расчёт по позиции 1 — ЛДСП 16 мм «Дуб сонома»

```
Потребность = 120 × 3,8 = 456 м²/мес
Рср = 456 / 22 = 20,73 м²/день
ΔР (по факту за 6 мес.) = 3,73 м²/день

Zmin = 1,65 × √(10 × 3,73² + 20,73² × 2²)
     = 1,65 × √(139,13 + 1718,92)
     = 1,65 × √1858,05
     = 1,65 × 43,10 ≈ 71,1 м²

ROP (без коррекции) = 20,73 × 10 + 71,1 = 278,4 м²

Коррекция на прогноз:
Zmin_корр = 71,1 × 1,15 ≈ 81,8 м²  → технологических ограничений нет → Zmin_итог = 82 м²
ROP_итог = 207,3 + 82 = 289,3 ≈ 289 м²
```

### 9.3. Расчёт по позиции 2 — Кромка ПВХ 0,4 мм

```
Потребность = 120 × 22 = 2640 м/мес
Рср = 2640 / 22 = 120 м/день
ΔР (по факту) = 18 м/день

Zmin = 1,96 × √(15 × 18² + 120² × 4²)
     = 1,96 × √(4860 + 230 400)
     = 1,96 × √235 260
     = 1,96 × 485,04 ≈ 950,7 м

ROP (без коррекции) = 120 × 15 + 950,7 = 2750,7 м

Коррекция на прогноз:
Zmin_корр = 950,7 × 1,15 ≈ 1093 м → ограничений MOQ по кромке нет → Zmin_итог = 1093 м
ROP_итог = 1800 + 1093 = 2893 м
```

### 9.4. Расчёт по позиции 3 — Направляющие раздвижные системы

```
Потребность = 120 × 1 = 120 компл./мес
Рср = 120 / 22 = 5,45 компл./день
ΔР (по факту, высокая волатильность импортных поставок) = 1,36 компл./день

Zmin = 2,33 × √(35 × 1,36² + 5,45² × 7²)
     = 2,33 × √(64,75 + 1455,3)
     = 2,33 × √1520,05
     = 2,33 × 38,99 ≈ 90,9 → округление вверх до целых = 91 компл.

Коррекция на прогноз:
Zmin_корр = 91 × 1,15 ≈ 104,7 → округление вверх = 105 компл.

Проверка технологического ограничения (Шаг 8):
Zтехнологический_минимум = MOQ = 100 компл.
Zmin_итог = max(105; 100) = 105 компл.

ROP_итог = 5,45 × 35 + 105 = 190,75 + 105 ≈ 296 компл.
```

| Позиция | Рср | Тпост, дн | Zmin_итог | ROP_итог | Ед. |
|---|---|---|---|---|---|
| ЛДСП «Дуб сонома» | 20,73 | 10 | 82 | 289 | м² |
| Кромка ПВХ 0,4 мм | 120,00 | 15 | 1093 | 2893 | м.пог |
| Направляющие раздвижные | 5,45 | 35 | 105 | 296 | компл. |

### 9.6. Проверка сигнала на закупку (Шаг 9) на текущих остатках

Условные фактические остатки на дату пилотного расчёта:

| Позиция | Остаток на складе | НЗП (в пути/резерв) | Ост + НЗП | ROP | Сигнал |
|---|---|---|---|---|---|
| ЛДСП «Дуб сонома» | 250 м² | 0 | 250 | 289 | Ниже ROP → заказ нужен |
| Кромка ПВХ 0,4 мм | 2000 м | 0 | 2000 | 2893 | Ниже ROP → заказ нужен |
| Направляющие раздвижные | 150 компл. | 20 компл. | 170 | 296 | Ниже ROP → заказ нужен |

Расчёт объёма заявки:

```
ЛДСП «Дуб сонома»:
  Потребность до поставки = 20,73 × 10 = 207,3 м²
  Заявка = 207,3 + 82 − 250 ≈ 39,3 → округление под формат листа/остатка ≈ 40 м²

Кромка ПВХ 0,4 мм:
  Потребность до поставки = 120 × 15 = 1800 м
  Заявка = 1800 + 1093 − 2000 ≈ 893 м

Направляющие раздвижные:
  Потребность до поставки = 5,45 × 35 = 190,75 компл.
  Заявка = 190,75 + 105 − 170 ≈ 125,75 компл.
  Округление до кратности MOQ (100) в бо́льшую сторону → заявка = 200 компл.
```

### 9.7. Выводы пилота

1. Алгоритм корректно отработал на трёх разных профилях риска: коротком локальном плече поставки (ЛДСП), среднем импортном (кромка) и длинном импортном с жёстким MOQ (направляющие) — во всех случаях получены отличающиеся, но объяснимые уровни Zmin и ROP.
2. Технологическое ограничение (MOQ) сработало только по направляющим — расчётный Zmin (91–105) оказался ниже или сопоставим с MOQ (100), что подтверждает необходимость шага 8 в алгоритме: без него минимальный запас по этой позиции был бы занижен относительно реальных условий поставщика.
3. Коррекция на прогноз (Кпрогноз = 1,15) увеличила Zmin по всем трём позициям на ~15%, что соответствует ожиданиям по предновогоднему пику — механизм работает предсказуемо и линейно.
4. Итоговая заявка на закупку по направляющим (200 компл.) на 74 компл. больше расчётной потребности (126) исключительно из-за округления под MOQ — это стоит учитывать в бюджете закупки и обсуждать с поставщиком возможность более мелкой кратности отгрузки.

### 9.8. Рекомендации по дальнейшему масштабированию

- Перед полным внедрением повторить пилот ещё на 2–3 изделиях с разными технологическими цепочками (например, мягкая мебель с тканью/поролоном), чтобы проверить формулу на позициях с иной волатильностью спроса.
- Зафиксировать пилотные результаты как baseline и сверить их через 1–2 месяца с фактическим расходом и фактами дефицита/затоваривания — это покажет, насколько верно подобраны Ксл и ΔР по каждой группе материалов.
- Автоматизировать расчёт ΔР и ΔТпост из учётной системы до масштабирования на весь каталог — ручной пересчёт оправдан только на пилотной выборке.
