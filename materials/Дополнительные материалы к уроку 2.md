# Задача: ежедневная проверка контрагентов по ИНН + проверка отзывов в 2ГИС

Ты работаешь в headless-режиме (claude -p), без возможности задать уточняющий
вопрос человеку. Пройди шаги строго по порядку. Если какой-то шаг невозможно
выполнить для конкретной компании — зафиксируй это в отчёте в разделе «Ошибки»
и продолжай с остальными, не прерывай весь запуск целиком.

## Контекст

Рабочая директория — корень этого проекта. В ней:
- `./input/` — сюда каждый день кладут новый файл (.xlsx или .csv) с таблицей
  компаний-контрагентов.
- `./output/` — сюда нужно сохранять готовые отчёты.
- `./processed.log` — список уже обработанных файлов (имя файла + дата
  обработки), чтобы не проверять один и тот же файл дважды.
- `APIFY_TOKEN` — переменная окружения с токеном Apify (уже установлена).

## Шаг 1. Найди новый файл

1. Пересмотри `./input/*.xlsx` и `./input/*.csv`.
2. Сравни со списком в `./processed.log`. Обрабатывай только те файлы,
   которых там ещё нет.
3. Если новых файлов нет — ничего не делай, ничего не создавай, просто выведи
   в stdout: `Нет новых файлов на <сегодняшняя дата>`. Дальнейшие шаги не
   выполняй.
4. Если новых файлов несколько — обработай каждый по очереди, в отчёте
   указывай имя исходного файла.

## Шаг 2. Прочитай таблицу

Ожидаемые колонки (порядок и точные названия могут немного отличаться —
сопоставляй по смыслу):

`Название компании | ИНН | Телефон | WhatsApp | Email | Сайт | Адрес`

Для .xlsx используй python (`openpyxl` или `pandas`), для .csv — обычное
чтение. ИНН читай как строку (не как число — важны ведущие нули и точность).

Из адреса вытащи город (после «г. »). Если город не указан явно — считай, что
это Санкт-Петербург.

## Шаг 3. Проверка контрагентов по ИНН

Собери список всех ИНН из файла и одним запросом вызови Apify actor
`isolovyev/ru-counterparty-check` через REST API:

```bash
curl -s -X POST \
  "https://api.apify.com/v2/acts/isolovyev~ru-counterparty-check/run-sync-get-dataset-items?token=${APIFY_TOKEN}&timeout=300" \
  -H "Content-Type: application/json" \
  -d '{
    "inns": ["ИНН1", "ИНН2", "..."],
    "mode": "search",
    "sources": ["fedresurs", "nalog", "rnp", "rosfinmonitoring"]
  }'
```

Из ответа по каждой компании возьми: `name`, `status`, `riskLevel`,
`riskScore`, `riskFactors[].description`, `fedresurs.bankruptcyStage`,
`fedresurs.legalCasesCount`, `nalog.liquidated`, `nalog.massFounderFlag`,
`nalog.taxRisk.massAddress`, `nalog.taxRisk.arrearsTotal`, `rnp.inRnp`,
`rosfinmonitoring.inFedsfmList`, `sanctioned`.

Если запрос вернул ошибку авторизации (401/403) — останови проверку по ИНН,
запиши в отчёт «Не удалось проверить контрагентов: неверный или истёкший
APIFY_TOKEN» и переходи к шагу 4 (2ГИС можно проверять независимо).

Если для батча компаний больше 15 — увеличь `timeout` в query-параметре до
600 и предупреди в логе, что запрос может идти дольше обычного (это нормально,
актор последовательно дёргает 4 официальных источника).

## Шаг 4. Проверка присутствия и отзывов в 2ГИС

Сгруппируй компании по городу (см. шаг 2). Для каждой группы вызови Apify
actor `m_mamaev/2gis-places-scraper` одним запросом на группу — этот актор
принимает массив запросов и один город на запрос:

```bash
curl -s -X POST \
  "https://api.apify.com/v2/acts/m_mamaev~2gis-places-scraper/run-sync-get-dataset-items?token=${APIFY_TOKEN}&timeout=180" \
  -H "Content-Type: application/json" \
  -d '{
    "query": ["Название компании 1", "Название компании 2", "..."],
    "locationQuery": "Город",
    "maxItems": 3,
    "maxReviewsPerPlace": 5,
    "includeContacts": false,
    "includeReviewerData": false,
    "includeUnratedReviews": false,
    "reviewRatings": "all",
    "reviewSortBy": "trust"
  }'
```

**Важно про сопоставление.** Актор ищет по названию нестрого и может вернуть
однофамильцев (например, три разных «Гермеса» по трём разным адресам).
Карточку считай найденной ТОЛЬКО если улица и номер дома в поле `address`
результата совпадают (с точностью до опечаток/сокращений) с адресом компании
из исходного файла. Если совпадения по адресу нет — считай, что карточка
компании в 2ГИС не найдена, даже если название похоже.

Для найденной карточки зафиксируй: `totalScore` (рейтинг),
`reviewsMeta.ratedCount` (реальное число отзывов — надёжнее, чем
`reviewsCount`), ссылку `url`.

## Шаг 5. Сформируй отчёт

Сохрани в `./output/report_<YYYY-MM-DD>.md` (дата — дата запуска) по шаблону:

```markdown
# Проверка контрагентов — <дата>
Источник: input/<имя файла>

## 1. Проверка по ИНН

| Компания | ИНН | Статус | Риск | Что нашли |
|---|---|---|---|---|
| ... | ... | ... | 🟢/🟡/🔴 | краткое описание risk factors |

## 2. Наличие отзывов на 2ГИС

| Компания | Карточка в 2ГИС | Рейтинг | Отзывы |
|---|---|---|---|
| ... | ✅/❌ + ссылка | ... | ... |

## Ошибки
(если были — иначе не создавай раздел)
```

Шкала риска для колонки «Риск»: `riskScore` 0–15 → 🟢 низкий,
16–40 → 🟡 средний, 41+ → 🔴 высокий (или если `sanctioned`/`rnp.inRnp`/
`rosfinmonitoring.inFedsfmList` = true — всегда 🔴, независимо от riskScore).

## Шаг 6. Отметь файл обработанным

Допиши в `./processed.log` строку вида `<имя файла>\t<дата обработки ISO>`.

## Ограничения и безопасность

- Не устанавливай новые пакеты и не меняй файлы вне `./input`, `./output`,
  `./processed.log`.
- Не проверяй больше 30 компаний за один запуск без явного изменения этого
  файла человеком — если файл больше, обработай первые 30 и укажи в отчёте,
  что остаток не проверен.
- Если один из двух Apify-запросов упал — не прерывай весь отчёт, просто
  отметь соответствующий раздел как «не удалось получить данные» и укажи
  причину.
